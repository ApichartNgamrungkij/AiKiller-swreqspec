# แผนทดสอบโหลด: การรองรับผู้ใช้งานพร้อมกัน 5,000 คน

## วัตถุประสงค์

ตรวจสอบว่าระบบจัดการตารางส่วนตัวและหน้ารายละเอียดกิจกรรมสามารถรองรับผู้ใช้งานพร้อมกันได้อย่างน้อย 5,000 คนตาม NFR-SCHED-01 และ ASM-SCHED-05

## ขอบเขต

- ทดสอบการเข้าถึงหน้า “ตารางของฉัน” และการตรวจสอบคาบเกี่ยวในหน้ารายละเอียดกิจกรรม
- ใช้การจำลองคิวการเข้าถึงเพื่อยืนยันว่าเมื่อผู้ใช้งานเกิน 5,000 คน จะต้องรอจนกว่าผู้ใช้ออกจากหน้าให้ย้ายผ่านได้
- ไม่รวมการลงทะเบียนกิจกรรมจริงหรือการจัดการตารางเรียนจากระบบมหาวิทยาลัย

## วิธีทดสอบ

1. ตั้งค่า Capacity เป็น 5,000 ผู้ใช้พร้อมกัน
2. เปิดโหมด parallel ให้ 5,001 ผู้ใช้เริ่มเข้าถึงพร้อมกัน
3. ตรวจว่าผู้ใช้คนที่ 5,001 ต้องรอจนกว่าผู้ใช้คนก่อนหน้าออกจากหน้า
4. เมื่อตอนหนึ่งมีผู้ใช้หลุดออกจากหน้าหรือจากกิจกรรมแล้ว ผู้ใช้ที่รอคิวจะได้รับสิทธิ์เข้าถึงต่อ
5. ตรวจว่าค่า active user ไม่เกิน 5,000 และไม่มีการละเมิด Constraint ของ NFR-SCHED-01

## เกณฑ์ผ่าน

- จำนวนผู้ใช้ที่ทำงานพร้อมกันไม่เกิน 5,000
- มีอย่างน้อย 1 ผู้ใช้ที่ต้องรอคิวเมื่อเกินขีดจำกัด
- ผู้ใช้ที่รอคิวได้รับสิทธิ์เข้าถึงต่อหลังจากผู้ใช้อื่นออกจากหน้าตารางส่วนตัวหรือหน้ากิจกรรม
- สคริปต์ทดสอบโหลดต้องทำงานโดยไม่บล็อกการเข้าใช้ฟีเจอร์จนกว่าโควตาจะเต็ม
