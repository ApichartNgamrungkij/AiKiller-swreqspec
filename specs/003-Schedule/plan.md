# แผนงาน: จัดการตารางส่วนตัว (Schedule)

อ้างอิงข้อกำหนด: [spec.md](./spec.md) (Draft v2)

## 1. สรุปแนวทาง

1. นักศึกษาที่เข้าสู่ระบบใช้หน้า “ตารางของฉัน” เพื่อเพิ่มและแก้ไขช่วงเวลาที่ไม่ว่าง (FR-SCHED-01, FR-SCHED-02)
2. บันทึกแต่ละรายการพร้อมวันเริ่ม/สิ้นสุดและเวลาเริ่ม/สิ้นสุด โดยช่วงเวลานั้นเกิดซ้ำทุกวัน รวมวันเริ่มและวันสิ้นสุด (FR-SCHED-02, FR-SCHED-03, ASM-SCHED-06)
3. ใช้ข้อมูลรายการของนักศึกษาคนปัจจุบันเท่านั้น และไม่ดึงข้อมูลตารางเรียนจากระบบมหาวิทยาลัย (IF-SCHED-01, ASM-SCHED-01)
4. เมื่อนักศึกษาดูรายละเอียดกิจกรรม ใช้วันเวลาเริ่ม/สิ้นสุดที่หน้ารายละเอียดมีอยู่แล้วเป็น input สำหรับตรวจช่วงเวลาคาบเกี่ยว (FR-SCHED-04, FR-SCHED-05, AC-SCHED-05, AC-SCHED-07)
5. แสดงคำเตือนโดยไม่ขวางการไปขั้นลงทะเบียน Google Form ซึ่งอยู่นอกขอบเขตของฟีเจอร์นี้ (DOM-SCHED-01, FR-SCHED-06, ASM-SCHED-03)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นตามคำสั่งของรายวิชา ไม่มีเทคโนโลยีหน้าบ้านใน Constraints |
| Python FastAPI สำหรับหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นตามคำสั่งของรายวิชา ไม่มีเทคโนโลยีหลังบ้านใน Constraints |
| เทคโนโลยีฐานข้อมูล/จัดเก็บข้อมูล | ทีมเลือกเอง ไม่ได้มาจาก spec | spec ไม่ได้ระบุฐานข้อมูล จึงไม่เลือกผลิตภัณฑ์หรือรูปแบบจัดเก็บในแผนนี้ (FR-SCHED-03) |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| PersonalBusyPeriod | `id`, `student_id`, `start_date`, `end_date`, `start_time`, `end_time` | เก็บช่วงเวลาส่วนตัวของนักศึกษาที่เกิดซ้ำทุกวันระหว่างวันที่ระบุ (FR-SCHED-02, FR-SCHED-03, ASM-SCHED-06) |
| ActivityTimeInput | `activity_start`, `activity_end` | ข้อมูลเวลาเริ่ม/สิ้นสุดที่หน้ารายละเอียดกิจกรรมมีอยู่แล้ว ส่งให้ตัวตรวจเปรียบเทียบ โดยไม่เพิ่ม entity สำหรับสร้างหรือแก้ไขกิจกรรม (FR-SCHED-04, Out of Scope: การสร้างหรือแก้ไขกิจกรรม) |

ไม่เก็บข้อมูลตารางเรียนจากระบบมหาวิทยาลัยโดยตรง (IF-SCHED-01) และไม่ทำ entity สำหรับการลงทะเบียนกิจกรรมจริง (Out of Scope: การลงทะเบียนกิจกรรมจริง)

## 4. API / หน้าจอ

- `GET /me/schedule` — อ่านรายการช่วงเวลาของนักศึกษาที่เข้าสู่ระบบและแสดงในหน้า “ตารางของฉัน” (FR-SCHED-01, FR-SCHED-03)
- `POST /me/schedule` — รับ `start_date`, `end_date`, `start_time`, `end_time`; บันทึกรายการใหม่และคืนรายการที่บันทึกแล้ว (FR-SCHED-02, FR-SCHED-03)
- `PUT /me/schedule/{period_id}` — รับวัน/เวลาใหม่; ปรับเฉพาะรายการที่ระบุและคงรายการอื่นไว้ (FR-SCHED-02, AC-SCHED-02)
- `POST /me/schedule/check-overlap` — รับวันเวลาเริ่ม/สิ้นสุดของกิจกรรมที่มีอยู่ในหน้ารายละเอียด; ส่งคืนสถานะและข้อความเตือนเมื่อมีช่วงทับกัน (FR-SCHED-04, FR-SCHED-05, AC-SCHED-05, AC-SCHED-07)
- `หน้า “ตารางของฉัน”` — แสดงและรับข้อมูลสำหรับเพิ่ม/แก้ไขรายการ โดยต้องเข้าถึงหลังล็อกอิน (FR-SCHED-01, FR-SCHED-02, CON-SCHED-01)
- `หน้ารายละเอียดกิจกรรม` — เรียกตัวตรวจด้วยข้อมูลวันเวลาที่หน้ามีอยู่ และแสดงคำเตือนพร้อมคงการไปยัง Google Form ได้ (FR-SCHED-04, FR-SCHED-05, FR-SCHED-06, DOM-SCHED-01, ASM-SCHED-03)

ชื่อ path ข้างต้นเป็นข้อเสนอเชิงออกแบบ ไม่ใช่ข้อกำหนด API จาก spec; ใช้ข้อมูลวันเวลาที่มีในหน้ารายละเอียดกิจกรรมตามคำตอบของทีมในรอบวางแผนนี้

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-SCHED-01 | จำกัดหน้าและ API ตารางส่วนตัวให้ใช้ได้หลังนักศึกษาเข้าสู่ระบบ และทดสอบการเปิดหน้าใน AC-SCHED-01 | ใช้แล้ว |
| IF-SCHED-01 | อ่าน/บันทึกเฉพาะข้อมูลที่นักศึกษากรอกเอง ไม่ดึงข้อมูลจากระบบมหาวิทยาลัย; ตรวจใน AC-SCHED-04 และ AC-SCHED-07 | ใช้แล้ว |
| DOM-SCHED-01 | แสดงคำเตือนในหน้ารายละเอียดกิจกรรมหรือก่อนขั้น Google Form โดยไม่ขัดขวางการไปต่อ; ตรวจใน AC-SCHED-05 และ AC-SCHED-06 | ใช้แล้ว |

## 7. ลำดับงาน

1. ตรวจรูปแบบข้อมูลและเงื่อนไขช่วงซ้ำทุกวัน/วันสิ้นสุดแบบรวมวัน พร้อมกำหนดการเปรียบเทียบแบบไม่รวมเวลาสิ้นสุด (FR-SCHED-02, ASM-SCHED-02, ASM-SCHED-06)
2. เชื่อมการอนุญาตเข้าถึงหน้าและ API เข้ากับสถานะการเข้าสู่ระบบ (CON-SCHED-01, FR-SCHED-01, AC-SCHED-01)
3. สร้างการอ่าน/บันทึกรายการช่วงเวลาของนักศึกษา โดยแยกข้อมูลตามเจ้าของรายการ (FR-SCHED-03, IF-SCHED-01, AC-SCHED-04)
4. สร้างหน้าตารางส่วนตัวและการเพิ่มรายการ โดยเพิ่มทีละรายการและรักษารายการเดิม (FR-SCHED-02, AC-SCHED-02, AC-SCHED-03)
5. เพิ่มการแก้ไขเฉพาะรายการที่เลือกและตรวจว่ารายการอื่นไม่เปลี่ยน (FR-SCHED-02, AC-SCHED-02)
6. เชื่อมวันเวลาในหน้ารายละเอียดกิจกรรมที่มีอยู่เข้ากับตัวตรวจช่วงทับกัน โดยไม่สร้างหรือแก้ไขกิจกรรม (FR-SCHED-04, FR-SCHED-05, AC-SCHED-05, AC-SCHED-07)
7. แสดงคำเตือนที่ไม่ขัดขวางการไปขั้น Google Form และตรวจว่าไม่มีการลงทะเบียนจริงในฟีเจอร์นี้ (DOM-SCHED-01, FR-SCHED-06, AC-SCHED-06)
8. ทดสอบกำลังรองรับผู้ใช้งานพร้อมกัน 5,000 คนและพฤติกรรมรอคิวเมื่อเกินจำนวนดังกล่าว (NFR-SCHED-01, ASM-SCHED-05)
9. รันทดสอบตาม AC-SCHED-01 ถึง AC-SCHED-07 และตรวจย้อนกลับกับ Traceability ใน spec (AC-SCHED-01–07)

## 8. สิ่งที่ยังไม่ทำ

- Open Questions ใน spec: ไม่มี
- ไม่สร้างการดึงข้อมูลตารางเรียนจากระบบมหาวิทยาลัย (IF-SCHED-01; Out of Scope).
- ไม่สร้างการค้นหา/กรองกิจกรรม, การลงทะเบียนจริง, การสร้าง/แก้ไขกิจกรรม หรือการลบช่วงเวลาส่วนตัว (Out of Scope).
