# specs/003-Schedule/spec.md

# Feature : จัดการตารางส่วนตัว (Schedule)


## Goal

นักศึกษาสามารถกรอกช่วงเวลาที่ตนเองไม่ว่าง เช่น ตารางเรียนหรือธุระส่วนตัว เพื่อให้ระบบนำข้อมูลไปเทียบกับวันเวลากิจกรรมในภายหลัง และแจ้งเตือนเมื่อพบว่าตารางชนกัน


## Scope

### In Scope

- เปิดหน้า "ตารางของฉัน"
- เพิ่มช่วงเวลาที่ไม่ว่างทีละรายการ
- บันทึกช่วงเวลาที่นักศึกษากรอกไว้
- นำข้อมูลตารางส่วนตัวไปเทียบกับวันเวลากิจกรรม
- แจ้งเตือนเมื่อกิจกรรมมีเวลาชนกับตารางส่วนตัว
- เมื่อพบเวลาชน ระบบแจ้งเตือนแต่ไม่บล็อกการลงทะเบียน


### Out Scope

- การดึงตารางเรียนจากระบบมหาวิทยาลัยโดยอัตโนมัติ
- การค้นหาและกรองกิจกรรม
- การลงทะเบียนกิจกรรมจริง
- การสร้างหรือแก้ไขกิจกรรม
- การแก้ไขหรือลบรายการในตารางส่วนตัว เนื่องจาก Requirement ต้นทางยังไม่ได้ระบุ


## Constraints

- CON-SCHED-01 นักศึกษาต้องเข้าสู่ระบบแล้วก่อนใช้งานฟีเจอร์จัดการตารางส่วนตัว

- IF-SCHED-01 ระบบต้องใช้ข้อมูลตารางที่นักศึกษากรอกไว้ในระบบ และห้ามดึงข้อมูลตารางเรียนจากระบบมหาวิทยาลัยโดยตรง

- DOM-SCHED-01 เมื่อวันเวลากิจกรรมชนกับตารางส่วนตัว ระบบต้องแจ้งเตือนนักศึกษาเท่านั้น และต้องไม่บล็อกการลงทะเบียน โดยให้นักศึกษาเป็นผู้ตัดสินใจเอง


## Requirements

FR-SCHED-01 ระบบต้องให้นักศึกษาเปิดหน้า "ตารางของฉัน" ได้หลังจากเข้าสู่ระบบแล้ว

FR-SCHED-02 ระบบต้องให้นักศึกษาเพิ่มช่วงเวลาที่ไม่ว่าง เช่น ตารางเรียนหรือธุระส่วนตัว ได้ทีละรายการ

FR-SCHED-03 ระบบต้องบันทึกข้อมูลช่วงเวลาที่นักศึกษากรอกไว้ เพื่อใช้ตรวจสอบกับกิจกรรมในภายหลัง

FR-SCHED-04 ระบบต้องนำข้อมูลตารางส่วนตัวของนักศึกษาไปเทียบกับวันเวลากิจกรรม

FR-SCHED-05 เมื่อวันเวลากิจกรรมทับซ้อนกับตารางส่วนตัว ระบบต้องแจ้งเตือนนักศึกษา

FR-SCHED-06 การตรวจพบเวลาทับซ้อนต้องไม่บล็อกการลงทะเบียนกิจกรรม


## Quality Requirements

- NFR-SCHED-01 ระบบต้องรองรับผู้ใช้งานได้อย่างน้อย ~5,000 คนต่อภาคการศึกษา


## Acceptance Criteria

- [ ] AC-SCHED-01

    Given นักศึกษาเข้าสู่ระบบแล้ว  
    When นักศึกษาเปิดหน้า "ตารางของฉัน"  
    Then ระบบแสดงหน้าสำหรับให้นักศึกษาเพิ่มช่วงเวลาที่ไม่ว่าง


- [ ] AC-SCHED-02

    Given นักศึกษาอยู่ในหน้า "ตารางของฉัน"  
    When นักศึกษากรอกช่วงเวลาที่ไม่ว่างและสั่งบันทึก  
    Then ระบบบันทึกช่วงเวลาดังกล่าวไว้ในตารางส่วนตัวของนักศึกษา


- [ ] AC-SCHED-03

    Given นักศึกษามีช่วงเวลาที่ไม่ว่างบันทึกไว้แล้วอย่างน้อยหนึ่งรายการ  
    When นักศึกษาเพิ่มช่วงเวลาที่ไม่ว่างอีกหนึ่งรายการ  
    Then ระบบบันทึกรายการใหม่โดยยังคงรายการเดิมไว้


- [ ] AC-SCHED-04

    Given นักศึกษาได้กรอกช่วงเวลาที่ไม่ว่างไว้ในระบบ  
    When ระบบบันทึกข้อมูลสำเร็จ  
    Then ข้อมูลดังกล่าวต้องสามารถนำกลับมาใช้ตรวจสอบวันเวลากิจกรรมในภายหลังได้


- [ ] AC-SCHED-05

    Given นักศึกษามีข้อมูลตารางส่วนตัวที่บันทึกไว้  
    And กิจกรรมมีวันเวลาทับซ้อนกับช่วงเวลาที่นักศึกษาบันทึกไว้  
    When ระบบตรวจสอบวันเวลากิจกรรมกับตารางส่วนตัว  
    Then ระบบแสดงข้อความแจ้งเตือนว่ามีเวลาชนกัน


- [ ] AC-SCHED-06

    Given กิจกรรมมีวันเวลาชนกับตารางส่วนตัวของนักศึกษา  
    When ระบบแสดงคำเตือนเรื่องเวลาชน  
    Then นักศึกษายังสามารถดำเนินการลงทะเบียนกิจกรรมต่อได้


- [ ] AC-SCHED-07

    Given นักศึกษาเคยบันทึกช่วงเวลาที่ไม่ว่างไว้ในระบบ  
    When นักศึกษาดูหรือลงทะเบียนกิจกรรมในภายหลัง  
    Then ระบบนำข้อมูลตารางส่วนตัวที่บันทึกไว้มาตรวจสอบกับวันเวลากิจกรรม


## Assumptions & Open Questions

- ASM-SCHED-01 ข้อมูลตารางส่วนตัวเป็นข้อมูลที่นักศึกษากรอกเอง ไม่ได้ดึงจากระบบตารางเรียนของมหาวิทยาลัย

- Q-SCHED-01 UC-05 ระบุ Requirement ที่เกี่ยวข้องเป็น R25 / US-24 แต่ Requirement List ปัจจุบันที่มีระบุเพียง R01-R11 — ต้องยืนยันว่า R25 เป็น Requirement ที่ตกหล่น หรือ UC-05 อ้าง Requirement ID ผิด

- Q-SCHED-02 R25 ระบุเฉพาะ "ตารางเรียนของนักศึกษา" แต่ UC-05 ระบุ "ตารางเรียนหรือธุระส่วนตัว" — ต้องยืนยันว่าการตรวจสอบเวลาชนครอบคลุมทั้งสองประเภทหรือไม่

- Q-SCHED-03 ยังไม่ระบุว่าช่วงเวลาที่นักศึกษากรอกเป็นวันที่เฉพาะ ตารางประจำสัปดาห์ หรือรองรับทั้งสองรูปแบบ

- Q-SCHED-04 ยังไม่ระบุว่าข้อมูลแต่ละรายการในตารางส่วนตัวต้องประกอบด้วยข้อมูลใดบ้าง เช่น ชื่อรายการ วันที่ เวลาเริ่ม และเวลาสิ้นสุด

- Q-SCHED-05 ยังไม่ระบุว่ากรณีช่วงเวลาหนึ่งสิ้นสุดตรงกับเวลาเริ่มของกิจกรรม เช่น ตาราง 09:00-10:00 และกิจกรรมเริ่ม 10:00 ถือว่าเวลาชนหรือไม่

- Q-SCHED-06 ชื่อ Use Case คือ "จัดการตารางส่วนตัว" แต่ Main Flow ระบุเฉพาะการเพิ่มและบันทึก — ต้องยืนยันว่านักศึกษาสามารถแก้ไขและลบรายการได้หรือไม่

- Q-SCHED-07 NFR ระบุว่าระบบต้องรองรับผู้ใช้ ~5,000 คนต่อภาคการศึกษา แต่ยังไม่ระบุว่าเป็นจำนวนผู้ใช้ทั้งหมดหรือจำนวนผู้ใช้พร้อมกัน และยังไม่มีเกณฑ์ response time สำหรับฟีเจอร์นี้
