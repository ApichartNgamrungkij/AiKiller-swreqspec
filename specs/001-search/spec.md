# Feature: ค้นหาและดูกิจกรรม (Search)
#specs/001-Search&Find/spec.md
#Feature : ดูและค้นหา (Search & Find)


## Goal
นักศึกษาที่ต้องการหากิจกรรมจิตอาสา เลือกกิจกรรม วันเวลาที่ต้องการเข้าและได้ข้อความลงทะเบียนสำเร็จ

## Scope
### In Scope
แสดงกิจกรรมที่มีอยู่ วันปฏิบัติกิจกรรม จำนวนคนที่รับ และชั่วโมงจิตอาสาที่จะได้รับ
แสดงสถานะ "เต็มแล้ว / ยังรับสมัคร" ต่อกิจกรรม
เทียบวันเวลากิจกรรมกับตารางส่วนตัวที่นักศึกษากรอกไว้เอง
แสดงรายละเอียดกิจกรรม ชั่วโมงที่ได้รับ, วันเวลา, สถานที่
### Out Scope
การลงทะเบียนจริง
การกรอก/แก้ไขตารางส่วนตัว
การสร้าง/แก้ไขกิจกรรมโดยผู้จัด

## Constraints
IF  ห้ามดึงข้อมูลจากระบบตารางเรียนของมหาวิทยาลัยโดยตรง — ต้องใช้เฉพาะข้อมูลตารางที่นักศึกษากรอกเองในระบบเท่านั้น
IF ห้ามรับประกันว่าสถานะ "เต็ม/ว่าง" เป็น real-time แบบเป๊ะ — ข้อมูลจำนวนผู้ลงทะเบียนดึงมาจาก Google Sheets ผ่าน API แบบ poll เป็นระยะ (ทุก 1–2 นาที) จึงมีความหน่วงได้เล็กน้อย
DOM ห้ามแสดงกิจกรรมที่ไม่ใช่ 1 ใน 5 ประเภทที่มหาวิทยาลัยรับรอง (วิชาการ, กีฬาฯ, ศิลปวัฒนธรรม, คุณธรรมจริยธรรม, บำเพ็ญประโยชน์) — ต้องบังคับเลือกประเภทตอนสร้างกิจกรรม (ควบคุมที่ UC-08 ไม่ใช่ที่นี่ แต่ UC-02 ต้องกรองตามประเภทเหล่านี้เท่านั้น)
IF ห้ามให้ระบบเป็นผู้ตัดสินใจแทนนักศึกษา เมื่อพบว่าตารางชนกัน — แจ้งเตือนเฉยๆ ห้าม block การดูรายละเอียดหรือลงทะเบียน
IF ต้องรองรับผู้ใช้งานพร้อมกันได้ในระดับ ~5,000 คน/ภาคการศึกษา (NFR-01) — การค้นหา/กรองต้องไม่ทำให้ระบบช้าลงเมื่อมีคนเข้าดูพร้อมกันจำนวนมาก

## Requirements

FR-SRCH-01 ระบบต้องแสดงกิจกรรมทั้งหมดพร้อมสถานะ "เต็มแล้ว/ยังรับสมัคร" เมื่อนักศึกษาเปิดหน้ารายการกิจกรรม
FR-SRCH-02 ระบบต้องให้นักศึกษากรองกิจกรรมตามประเภทกิจกรรม หรือช่วงเวลาว่าง
FR-SRCH-03 ระบบต้องแสดงผลลัพธ์ที่กรองแล้วให้นักศึกษา
FR-SRCH-04 เมื่อไม่มีกิจกรรมตรงกับเงื่อนไขที่กรอง ระบบต้องแสดงข้อความ "ไม่พบกิจกรรมที่ตรงกับเงื่อนไข"                                       <-
FR-SRCH-05 ระบบต้องแสดงรายละเอียดกิจกรรม (ชั่วโมงที่ได้รับ, วันเวลา, สถานที่) เมื่อนักศึกษาเลือกดูกิจกรรมที่สนใจ

## Quality Requirements
NFR ระบบต้องรองรับผู้ใช้งานได้อย่างน้อย ~5,000 คนต่อภาคการศึกษา
NFR กระบวนการเตรียมข้อมูลให้พร้อมส่งเข้า REG ต้องทำได้ภายใน 1 วันทำการเมื่อเอกสารครบถ้วน
NFR ระบบต้องส่งข้อมูลระหว่างผู้ใช้กับเซิร์ฟเวอร์ผ่านการเข้ารหัส (HTTPS) เพื่อปกป้องข้อมูลส่วนตัวของนักศึกษา
NFR ระบบต้องมี Audit Log บันทึกการอนุมัติ/ปฏิเสธเอกสารของ Admin เพื่อตรวจสอบย้อนหลังได้

## Acceptance Criteria
- [] AC-SRCH-01
  Given กิจกรรมทั้งหมดที่ผู้จัดสร้างไว้ในระบบ
  When นักศึกษาเปิดหน้ารายการกิจกรรม
  Then แสดงกิจกรรมพร้อมสถานะ "เต็มแล้ว/ยังรับสมัคร" กำกับทุกรายการ
- []  AC-SRCH-02
  Given มีกิจกรรมในระบบที่จัดประเภทตามกิจกรรมทั้ง 5 ด้าน  When นักศึกษาเลือกกรองตามประเภทกิจกรรม 1 ใน 5 ด้าน  Then ระบบแสดงเฉพาะกิจกรรมที่ตรงกับประเภทที่เลือกเท่านั้น
-[] AC-SRCH-03
   Given นักศึกษาได้กรอกตารางเวลาของตนเองไว้ในระบบแล้ว  When นักศึกษาเลือกกรองกิจกรรมตามช่วงเวลาว่าง  Then ระบบตัดกิจกรรมที่มีเวลาชนกับตารางของนักศึกษาออกจากผลลัพธ์ หรือแสดงเครื่องหมายเตือนอย่างชัดเจน
- [] AC-SRCH-04
  Given นักศึกษาอยู่ในหน้ารายการกิจกรรม  When นักศึกษาเปิดดูรายละเอียดกิจกรรม  Then ระบบแสดงจำนวนชั่วโมงที่จะได้รับและระยะเวลาของกิจกรรมให้นักศึกษาเห็นก่อนกดปุ่มลงทะเบียน
- [] AC-SRCH-05
  Given ไม่มีกิจกรรมในระบบที่ตรงกับเงื่อนไขการกรองที่นักศึกษาเลือก  When นักศึกษาใช้เงื่อนไขดังกล่าวกรองรายการกิจกรรม  Then ระบบแสดงข้อความแจ้งอย่างชัดเจนว่าไม่พบกิจกรรมที่ตรงกับเงื่อนไข แทนการแสดงหน้าว่างเปล่า
- [] AC-SRCH-06
  Given ผู้จัดสร้างกิจกรรมใหม่สำเร็จแล้ว  When นักศึกษาเปิดหน้ารายการกิจกรรม  Then ระบบแสดงกิจกรรมที่เพิ่งสร้างใหม่ในรายการทันที โดยไม่ต้องรอ Admin อนุมัติ
- [] AC-SRCH-07
  Given กิจกรรมมีสถานะ “ยังรับสมัคร” และมีผู้ลงทะเบียนยังไม่ครบจำนวนที่กำหนด  When มีผู้ลงทะเบียนครบจำนวนที่กิจกรรมรองรับ  Then ระบบอัปเดตสถานะกิจกรรมเป็น “เต็มแล้ว” ให้นักศึกษาเห็นภายใน 2 นาที
- [] AC-SRCH-08
  Given นักศึกษาเข้าใช้งานระบบผ่านโทรศัพท์มือถือ  When นักศึกษาเปิดหน้ารายการกิจกรรม ใช้ตัวกรอง และดูรายละเอียดกิจกรรม  Then นักศึกษาสามารถใช้งานได้อย่างลื่นไหล โดยไม่ต้องขยายหน้าจอด้วยการ pinch-zoom หรือเลื่อนหน้าจอในแนวนอน

## Assumptions & Open Questions
- ASM-01 "ช่วงเวลาว่าง" สำหรับการกรอง หมายถึงการเทียบกับตารางส่วนตัวที่กรอกไว้ใน UC-05 (ระบุไว้ในวงเล็บของ main flow ขั้น 3)
- Q-01 เอกสารต้นทางระบุ "Requirement ที่เกี่ยวข้อง: R01, R02, R03, R" ซึ่งข้อความดูเหมือนถูกตัดตอน —  ต้องยืนยันรายการ requirement ID ที่ครบถ้วนก่อนทำ Traceability
- Q-02 ยังไม่มี Constraints/NFR สำหรับ UC-02 นี้ — ต้องตรวจสอบว่าจะอ้างอิงชุดเดียวกับ SPEC-BKG-001  (เช่น performance, ความปลอดภัยของข้อมูล) หรือมีชุดของตัวเอง
- Q-03 ไม่ระบุว่าสถานะ "เต็มแล้ว/ยังรับสมัคร" ต้องเป็น real-time หรือมี refresh/cache interval
