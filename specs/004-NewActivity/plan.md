# Plan: สร้างกิจกรรมใหม่

## 1. วัตถุประสงค์

สร้างฟีเจอร์ให้ผู้จัดกิจกรรมสามารถสร้างกิจกรรมใหม่ได้ตามขอบเขตและข้อกำหนดใน [spec.md](./spec.md) โดยยึดข้อสรุปจากการ Clarify ที่ทีมตอบไว้แล้ว:
- ผู้จัดต้องยืนยันอีกครั้งก่อนบันทึกกิจกรรมจริง ๆ
- Required field ได้แก่ ชื่อ / ประเภทกิจกรรม / วันเวลาที่จัด / สถานที่ / จำนวนรับ / ชั่วโมงจิตอาสาที่จะได้รับ
- URL สำหรับลงทะเบียนสามารถเป็น URL อะไรก็ได้ที่ผู้จัดเตรียมไว้
- กิจกรรมสามารถมีหลายรอบในวันเดียวกัน เช่น เช้า/บ่าย
- ผู้จัดสามารถแก้ไขกิจกรรมได้ และระบบต้องบันทึก edit log
- เมื่อยกเลิกกิจกรรม ระบบต้องแจ้งเตือนผู้ที่ลงทะเบียน

## 2. ขอบเขตการออกแบบ

### ระบบหลักที่ต้องรองรับ
- หน้า "สร้างกิจกรรมใหม่" สำหรับผู้จัดกิจกรรมที่มีสิทธิ์
- ฟอร์มกรอกข้อมูลกิจกรรม
- การตรวจสอบความครบถ้วนของข้อมูลก่อนบันทึก
- การยืนยันอีกครั้งก่อนบันทึกจริง
- การบันทึกกิจกรรมและทำให้กิจกรรมปรากฏในรายการที่นักศึกษาจะเห็น
- การบันทึกประวัติการแก้ไขกิจกรรม
- การยกเลิกกิจกรรมพร้อมการแจ้งเตือนผู้ที่ลงทะเบียน

### ขอบเขตที่ไม่รวม
- การขออนุมัติจากมหาวิทยาลัย
- การขออนุมัติงบประมาณ
- การขออนุมัติชั่วโมงจิตอาสา
- การจัดการสิทธิ์ผู้จัดกิจกรรม
- กระบวนการลงทะเบียนของนักศึกษา
- การสร้าง Google Form จาก template

## 4. แนวทางการพัฒนา

### 4.1 ฟอร์มและ validation
- สร้างหน้า "สร้างกิจกรรมใหม่" สำหรับผู้จัดที่มีสิทธิ์
- ต้องมี field ตาม FR-ACT-02 และ ASM-ACT-03:
  - ชื่อกิจกรรม
  - ประเภทกิจกรรม
  - วันเวลาที่จัด
  - สถานที่ที่จัด
  - จำนวนรับสมัคร
  - ชั่วโมงจิตอาสาที่จะได้รับ
  - URL สำหรับลงทะเบียน
- validation สำหรับ required field และรูปแบบข้อมูล (เช่น วันที่/เวลา/URL)
- message แจ้งช่องที่ยังต้องกรอกเมื่อมีข้อมูลไม่ครบ

### 4.2 ขั้นตอนสร้างกิจกรรม
1. ผู้จัดเปิดหน้า create
2. ระบบแสดงฟอร์มพร้อมข้อมูล required field
3. ผู้จัดกรอกข้อมูล
4. ระบบตรวจสอบข้อมูลที่จำเป็น
5. หากครบถ้วน ให้แสดงหน้าตรวจสอบอีกครั้งเพื่อยืนยันก่อนบันทึกจริง
6. เมื่อยืนยัน ระบบบันทึกกิจกรรม
7. ระบบทำให้กิจกรรมปรากฏในรายการกิจกรรมที่นักศึกษาเห็นได้

### 4.3 การจัดการวันเวลา
- ใช้รูปแบบ schedule/slots เพื่อรองรับหลายรอบในวันเดียวกัน เช่น เช้า/บ่าย
- คงให้หนึ่งกิจกรรมเป็นหน่วยเดียว แม้จะมีหลาย slot
- ไม่ใช้การสร้างกิจกรรมแยกต่อรอบตามที่ spec ระบุชัด

### 4.4 การแก้ไขและยกเลิก
- เพิ่มการแก้ไขกิจกรรมใน workflow ที่มีอยู่
- บันทึก edit log ทุกครั้งที่มีการเปลี่ยนแปลงข้อมูลกิจกรรม
- เพิ่ม state/flag สำหรับยกเลิกกิจกรรม
- เมื่อยกเลิกกิจกรรม ระบบต้องแจ้งเตือนผู้ที่ลงทะเบียนว่ากิจกรรมถูกยกเลิกแล้ว

## 5. Traceability ที่คาดว่าจะใช้

- FR-ACT-01 → หน้าสร้างกิจกรรมใหม่
- FR-ACT-02 → ฟอร์มกรอกข้อมูล required fields
- FR-ACT-03 → field URL สำหรับลงทะเบียน
- FR-ACT-04 → validation และ alert ช่องข้อมูลที่ขาด
- FR-ACT-05 → flow ยืนยันและบันทึกกิจกรรม
- FR-ACT-06 → การเผยแพร่ให้เห็นในรายการกิจกรรม
- FR-ACT-07 → ไม่เพิ่มกระบวนการอนุมัติใหม่
- FR-ACT-08 → edit log
- FR-ACT-09 → notification ยกเลิกกิจกรรม
- AC-ACT-01 ถึง AC-ACT-09 → ทดสอบตาม scenario ที่กำหนด

## 6. ความเสี่ยงและข้อควรระวัง
- ต้องไม่ขยาย scope เพิ่มกระบวนการอนุมัติใหม่หรือการสร้าง Google Form จาก template
- ต้องจัดการ payload วันเวลาให้สอดคล้องกับหลายรอบในวันเดียวกัน
- ต้องคงความสัมพันธ์ระหว่างกิจกรรมและผู้ที่ลงทะเบียนเมื่อลบ/ยกเลิกกิจกรรม
- ควรทดสอบคู่กับ requirement ที่มีการยืนยันก่อนบันทึกจริง และการแจ้งเตือนเมื่อยกเลิก
