# Feature : ดูข้อมูลผู้ลงทะเบียนจาก Google Sheets (ViewInfo)

## Goal
ตัวแทนองค์การนักศึกษา (ผู้จัดกิจกรรม) สามารถเปิดดูจำนวนและรายชื่อผู้ลงทะเบียนเข้าร่วมกิจกรรมของตนเองได้แบบเกือบเรียลไทม์ (Near Real-time) เพื่อติดตามและบริหารจัดการกิจกรรมได้อย่างมีประสิทธิภาพ

---

## Scope

### In Scope
- ผู้จัดกิจกรรมเปิดดูหน้ารายละเอียดกิจกรรมของตนเองที่มีผู้ลงทะเบียนอย่างน้อย 1 คน
- ระบบเชื่อมต่อและดึงข้อมูลรายชื่อ/จำนวนผู้ตอบกลับจาก Google Sheets ที่ผูกไว้กับ Google Form ของกิจกรรมผ่าน Google Sheets API
- ระบบแสดงจำนวนผู้ลงทะเบียนล่าสุด โดยอัปเดตข้อมูลทุก 1–2 นาที
- ระบบแสดงข้อมูลล่าสุดเท่าที่เคยดึงได้ พร้อมระบุวันเวลาอัปเดตล่าสุด (Last Updated Time) หากการเชื่อมต่อ Google Sheets API ล้มเหลว
- การจำกัดสิทธิ์ให้เฉพาะ Admin และผู้จัดกิจกรรมเจ้าของกิจกรรมเท่านั้นที่สามารถดูข้อมูลผู้ลงทะเบียนได้

### Out Scope
- การลงทะเบียนกิจกรรมของนักศึกษา (UC-03)
- การดาวน์โหลดหรือส่งออกไฟล์รายชื่อผู้ลงทะเบียนเป็น Excel/CSV (UC-11)
- การแก้ไข/ลบ ข้อมูลผู้ลงทะเบียนใน Google Sheets ผ่านหน้าเว็บไซต์
- การเช็คชื่อผู้เข้าร่วมกิจกรรมหน้างาน
- การนำรายชื่อผู้ลงทะเบียนเข้าสู่ระบบ REG ของมหาวิทยาลัย

---

## Constraints

- **IF-VIEW-01**: ระบบต้องดึงข้อมูลจำนวนและรายชื่อผู้ลงทะเบียนจาก Google Sheets ที่ผูกไว้กับ Google Form ผ่าน Google Sheets API โดยใช้กลไก Polling ทุก 1–2 นาที
- **IF-VIEW-02**: หากไม่สามารถเชื่อมต่อ Google Sheets API ได้ ระบบต้องแสดงข้อมูลล่าสุดที่เคยดึงสำเร็จพร้อมแจ้งเวลาที่อัปเดตล่าสุด ห้ามแสดงหน้าจอผิดพลาด (Crash) หรือหน้าเปล่า
- **ACC-VIEW-01**: สิทธิ์การเข้าถึงข้อมูลผู้ลงทะเบียนจำกัดเฉพาะ Admin และตัวแทนองค์การนักศึกษา (ผู้จัดกิจกรรม) ที่เป็นเจ้าของกิจกรรมนั้นๆ เท่านั้น
- **ACC-VIEW-02**: นักศึกษาทั่วไปต้องไม่สามารถเปิดดูรายชื่อหรือข้อมูลส่วนตัวของผู้ลงทะเบียนคนอื่นผ่านระบบได้
- **CON-VIEW-01**: กิจกรรมต้องมีผู้ลงทะเบียนผ่าน Google Form แล้วอย่างน้อย 1 คน ระบบจึงจะเริ่มแสดงข้อมูลผู้ลงทะเบียน

---

## Requirements

- **FR-VIEW-01**: ระบบต้องอนุญาตให้ผู้จัดกิจกรรมเปิดดูหน้ารายละเอียดกิจกรรมของตนเองเพื่อตรวจสอบข้อมูลผู้ลงทะเบียนได้
- **FR-VIEW-02**: ระบบต้องเชื่อมต่อกับ Google Sheets API เพื่อดึงข้อมูลจำนวนและรายชื่อผู้ลงทะเบียนของกิจกรรมนั้นๆ
- **FR-VIEW-03**: ระบบต้องแสดงจำนวนผู้ลงทะเบียนปัจจุบันแบบเกือบเรียลไทม์ (อัปเดตตามรอบการดึงข้อมูลทุก 1–2 นาที)
- **FR-VIEW-04**: ในกรณีที่การเชื่อมต่อ Google Sheets API ล้มเหลว ระบบต้องแสดงข้อมูลล่าสุดที่เคยบันทึกไว้ในแคช/ฐานข้อมูล พร้อมระบุวันและเวลาที่มีการอัปเดตข้อมูลล่าสุดให้ผู้จัดกิจกรรมทราบ
- **FR-VIEW-05**: ระบบต้องจำกัดการเข้าถึงหน้าแสดงข้อมูลผู้ลงทะเบียน ให้ดูได้เฉพาะผู้จัดกิจกรรมเจ้าของกิจกรรมและ Admin เท่านั้น

---

## Quality Requirements

- **NFR-PERF-01**: ระบบต้องดึงข้อมูลและอัปเดตแสดงผลจำนวนผู้ลงทะเบียนให้ตรงกับ Google Sheets ภายในเวลา 2 นาที (120 วินาที)
- **NFR-SEC-01**: ระบบต้องส่งผ่านข้อมูลระหว่างเซิร์ฟเวอร์กับผู้ใช้งานผ่านโปรโตคอลความปลอดภัย (HTTPS) เพื่อคุ้มครองข้อมูลส่วนบุคคลของผู้ลงทะเบียน
- **NFR-SEC-02**: ระบบต้องตรวจสอบและยืนยันสิทธิ์ (Authorization) ทุกครั้งที่มีการเรียกขอดูข้อมูลผู้ลงทะเบียน

## Acceptance Criteria

- [ ] **AC-VIEW-01**
  - **Given** มีนักศึกษาลงทะเบียนผ่าน Google Form ของกิจกรรมแล้วอย่างน้อย 1 คน
  - **When** ผู้จัดกิจกรรมเปิดหน้ารายละเอียดกิจกรรมของตนเอง
  - **Then** ระบบต้องแสดงจำนวนและรายชื่อผู้ลงทะเบียนล่าสุดที่ดึงมาจาก Google Sheets ผ่าน API

- [ ] **AC-VIEW-02**
  - **Given** มีผู้ลงทะเบียนใหม่กรอกข้อมูลผ่าน Google Form
  - **When** เวลาผ่านไปไม่เกิน 2 นาที
  - **Then** ระบบต้องอัปเดตแสดงจำนวนผู้ลงทะเบียนใหม่บนหน้าจอของผู้จัดกิจกรรมโดยอัตโนมัติหรือเมื่อมีการรีเฟรชหน้า

- [ ] **AC-VIEW-03**
  - **Given** ระบบไม่สามารถเชื่อมต่อ Google Sheets API ได้ (เช่น API Down หรือ Network Connection Error)
  - **When** ผู้จัดกิจกรรมเข้าดูหน้ารายละเอียดผู้ลงทะเบียน
  - **Then** ระบบต้องแสดงข้อมูลผู้ลงทะเบียนล่าสุดเท่าที่เคยดึงได้ พร้อมข้อความแจ้งเตือนระบุเวลาอัปเดตล่าสุด (เช่น "แสดงข้อมูลล่าสุดเมื่อ [วัน/เวลา]")

- [ ] **AC-VIEW-04**
  - **Given** ผู้ใช้งานเข้าสู่ระบบด้วยบัญชีนักศึกษาทั่วไป
  - **When** พยายามเข้าถึงหน้าดูข้อมูลผู้ลงทะเบียนของกิจกรรม
  - **Then** ระบบต้องปฏิเสธการเข้าถึงและแสดงข้อความแจ้งเตือนไม่มีสิทธิ์ใช้งาน (Access Denied)

- [ ] **AC-VIEW-05**
  - **Given** ผู้ใช้งานเข้าสู่ระบบด้วยบัญชี Admin หรือตัวแทนองค์การนักศึกษาผู้จัดกิจกรรมนั้น
  - **When** เข้าใช้งานหน้าดูข้อมูลผู้ลงทะเบียน
  - **Then** ระบบต้องอนุญาตให้เข้าถึงและแสดงข้อมูลผู้ลงทะเบียนได้อย่างถูกต้อง

## Assumptions & Open Questions

- **ASM-VIEW-01**: Google Sheets ของแต่ละกิจกรรมถูกกำหนดและเชื่อมโยงสิทธิ์การเข้าถึงผ่าน Service Account ที่ระบบใช้เรียก Google Sheets API เรียบร้อยแล้ว
- **ASM-VIEW-02**: การอัปเดตข้อมูลแบบเกือบเรียลไทม์ใช้วิธีเรียก API เป็นระยะ (Polling Every 1–2 Minutes) ซึ่งเพียงพอต่อความต้องการของผู้จัดกิจกรรม
- **Q-VIEW-01**: ตกลงให้แสดง `studentId`, `fullName`, `faculty`, `email` และ `timestamp` บนหน้าเว็บ โดยไม่แสดงคอลัมน์อื่นนอกเหนือจากนี้
- **Q-VIEW-02**: ยังไม่เพิ่ม Pagination หรือการค้นหารายชื่อในขอบเขตฟีเจอร์นี้ ให้แสดงรายการตามข้อมูลที่ได้รับก่อน

### ข้อตกลงเพิ่มเติมจากการชี้แจง

- API response ใช้ฟิลด์ `activityId`, `totalRegistered`, `lastSyncedAt`, `syncStatus`, `isCache` และ `data`
- เมื่อยังไม่มีผู้ลงทะเบียน API ตอบ `200 OK` พร้อม `totalRegistered: 0` และ `data: []`; หน้าจอแสดง Empty State
- เจ้าของกิจกรรมเก็บในฟิลด์ `owner_id` ของกิจกรรม และตรวจเทียบกับ `user_id` ของผู้ใช้งาน
- ใช้ APScheduler สำหรับ Polling และ Database Cache สำหรับเก็บข้อมูลล่าสุดที่ดึงสำเร็จ โดยเป็นการเลือกของทีม ไม่ได้มาจาก spec
